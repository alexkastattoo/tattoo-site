# Обновление Alex Kas Studio Manager

## 1. Обновление базы и файла

1. В старой версии календаря нажмите Backup & data → Export backup и сохраните копию.
2. Откройте `supabase-setup.sql`, скопируйте весь текст от `begin;` до `commit;` включительно в **новый** запрос Supabase SQL Editor и нажмите Run. Скрипт добавляет поля и командный доступ. Он не удаляет существующие записи. Если возникает ошибка — не заменяйте файл сайта, пришлите текст ошибки.
3. Замените `kas-web/index.html` обновлённым `index.html`. Publishable key уже перенесён из вашего локального файла. Секретные ключи и пароль Gmail в HTML не добавляются.
4. После обновления сайта обновите страницу без кеша (на Mac ⌘⇧R).
5. Войдите существующим аккаунтом и нажмите **Create studio**. Существующие записи этого аккаунта войдут в общий календарь. Создавать студию нужно один раз.

## 2. Сотрудники

В общем календаре все участники студии видят и редактируют все записи.

1. Владелец открывает **Studio team → Create invitation code → Copy code** и лично передаёт код сотруднику.
2. Сотрудник нажимает **Create account**, указывает своё имя, email и пароль, подтверждает email и входит.
3. После входа сотрудник выбирает **Join studio** и вставляет код. Ему не нужно создавать свою студию.
4. Код одноразовый и действителен 7 дней. Для каждого следующего сотрудника создаётся новый код; новый код отменяет предыдущий.
5. Владелец может убрать сотрудника кнопкой **Remove**. Записи сохраняются, доступ к общему календарю закрывается. Уже скачанные сотрудником копии данных отозвать невозможно.

Регистрация сама по себе не открывает чужой календарь. Для доступа нужен код приглашения. Одна учётная запись состоит в одной студии.

## 3. Gmail для писем регистрации

В вашем проекте проверено: custom SMTP выключен. Стандартная почта Supabase ограничивает получателей и отправки; для сотрудников нужно настроить SMTP. Изменения HTML сами по себе доставку не включают.

1. В аккаунте Google включите двухэтапную проверку, если ещё не включена: https://myaccount.google.com/security
2. Откройте https://myaccount.google.com/apppasswords и создайте пароль приложения, например «Alex Kas Studio». Если пункта нет, проверьте двухэтапную проверку и ограничения своего Google-аккаунта. Обычный пароль Google для SMTP не используйте.
3. В Supabase откройте **Authentication → Emails → SMTP Settings**:
   https://supabase.com/dashboard/project/cvvaakuvdgayvtrdikfw/auth/smtp
4. Включите **Enable custom SMTP** и заполните:
   - Sender email address: ваш полный Gmail-адрес.
   - Sender name: Alex Kas Studio.
   - Host: smtp.gmail.com
   - Port: 587 (TLS / STARTTLS).
   - Username: тот же полный Gmail-адрес.
   - Password: созданный пароль приложения Google.
5. Пароль вводите сами непосредственно в Supabase. Не вставляйте его в HTML, SQL или чат. Сохраните настройки.
6. **Authentication → Sign In / Providers**: проверьте, что Email и новые регистрации разрешены. Подтверждение email оставьте включённым.
7. **URL Configuration**: Site URL — https://alexkastattoo.ca/kas-web/ ; добавьте тот же точный адрес в Redirect URLs. Во время проверки Site URL был правильным, но список Redirect URLs был пуст.
8. Зарегистрируйте один новый тестовый адрес. Проверьте входящие и спам. Для существующего неподтверждённого аккаунта повторная отправка находится внутри окна Create account. Между запросами выждите не менее минуты; открывайте только последнее письмо.
9. Если Supabase сообщает ошибку отправки, проверьте **Authentication → Audit Logs** и настройки SMTP. Доставка писем здесь ещё не проверена с реальным новым пользователем.

Документация:
- Supabase SMTP: https://supabase.com/docs/guides/auth/auth-smtp
- Google, пароли приложений: https://support.google.com/accounts/answer/185833
- Gmail SMTP: https://developers.google.com/workspace/gmail/imap/imap-smtp

## 4. Карточки и несколько дней

- Телефон, соцсеть и email — отдельные поля. Старое объединённое контактное поле сохранено в Phone, чтобы ничего не потерять; при редактировании можно вручную перенести соцсеть в Social / Instagram.
- **Artist** назначает мастера, **Color** выбирает цвет записи.
- **Title / event** задаёт заголовок, например «Berlin guest spot». Можно заполнить только заголовок без клиента.
- **Date** — первый день, **Through date (inclusive)** — последний, включительно. Для одного дня укажите одинаковые даты.
- Событие на несколько дней хранится одной записью. В месяце оно показано цветной полосой, в неделе и дне — в строке Multi-day. При переходе через неделю полоса продолжается на следующей строке календаря.
- Удаление такой записи удаляет весь диапазон, а редактирование меняет весь диапазон сразу.
- Время выбирается с шагом 15 минут. Старые записи с другим временем не округляются.

## Проверки этой версии

В изолированной PostgreSQL-базе проверены повторное применение SQL, сохранение старой записи, общие чтение/изменение сотрудником, отсутствие доступа у посторонних, одноразовость и срок приглашений, отзыв доступа без удаления записей и ограничения цвета/дат. Проверены формы и отображение на тестовых данных. Изменения ещё не применены к вашей рабочей базе или GitHub; отправка писем через Gmail требует настройки выше.
